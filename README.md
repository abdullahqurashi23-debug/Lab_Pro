# LabPro

Offline desktop laboratory report management system. Electron + React 18 +
TypeScript + Vite on the front end, SQLite (via `better-sqlite3`) embedded
directly in the app's main process — no external database server, no
internet connection needed to run it.

## Stack

- Electron + React 18 + Vite + TypeScript
- Tailwind CSS + shadcn/ui (Radix primitives) + lucide-react icons
- better-sqlite3, embedded, single-file database (`labpro.db` in the OS
  per-user app data folder), WAL journal mode, numbered SQL migrations
- fuse.js (fuzzy search), recharts (charts), xlsx/SheetJS (Excel
  import/export), bcryptjs (the admin password hash), zod (IPC input
  validation)

## Project layout

```
electron/
  main/index.ts       Electron main process — window, all ipcMain handlers
  preload/index.ts     contextBridge — the only thing the renderer can call
src/
  db/                 SQLite layer (main-process-only, despite living under src/)
    migrations/       numbered .sql files, applied in order, tracked in
                       a schema_migrations table
    db.ts             opens labpro.db, sets pragmas, runs migrations
    api.ts            all queries — the single source of truth for the schema
    excel.ts          SheetJS import/export helpers
    validation.ts     zod schemas — every IPC payload is validated here
  pages/              one file per route
  components/         Sidebar, TopBar, and components/ui (shadcn primitives)
  lib/                api.ts (typed window.api wrapper), types.ts, theme.ts
build/
  icon.ico / icon.png generated by `npm run generate-icon` (scripts/generate-icon.mjs)
```

## Install

```bash
npm install
```

`postinstall` runs `electron-rebuild` automatically so `better-sqlite3`'s
native binding is rebuilt against Electron's Node ABI (not your system
Node's) — this is required and normal.

## Run in development

```bash
npm run dev
```

This runs three things together: the Vite dev server (renderer), a `tsc
--watch` compile of `electron/` + `src/db/` to `dist-electron/`, and Electron
itself once both are ready. The database file is created automatically on
first launch, at your OS's app-data path for LabPro, and the test catalog is
seeded automatically.

First launch asks you to set the admin password (a single screen-lock
password, not multi-user accounts) — you'll need it every time LabPro opens.

## Build the Windows installer

```bash
npm run generate-icon   # only needed once, or after changing build/icon.ico's design
npm run dist
```

`npm run dist` compiles everything and runs electron-builder with the NSIS
target, producing a Windows installer under `dist-electron-installer/` (or
wherever electron-builder's default output folder lands for your
electron-builder version — check the terminal output for the exact path).
better-sqlite3's native `.node` binary is unpacked from the app's `asar`
archive automatically (see `build.asarUnpack` in `package.json`) so it loads
correctly from the installed `.exe`.

## Database migrations

Add a new file to `src/db/migrations/`, named `<next-number>_<name>.sql`
(e.g. `002_add_patient_notes.sql`). On next launch, LabPro applies any
migration not yet recorded in the `schema_migrations` table, in order, inside
a transaction — existing installations upgrade in place without losing data.
Never edit an already-shipped migration file; add a new one instead.

## The one rule that can't be broken

A finalized (printed) report can never be edited or deleted. This is
enforced twice: the application code refuses the operation, and SQLite
triggers inside `001_init.sql` refuse it too — even a bug in the UI, or
someone opening the `.db` file directly in another tool, can't alter a
printed report.
